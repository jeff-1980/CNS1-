# paperB 更正 · 第 0 步：只换测试端 Normal 窗口的重新推理（2026-11-03）

依据 `results/paperB_correction/ASSESSMENT.md`（f96b1ae）第 4 节，jeff 2026-11-03 授权。

## 范围与约束

- **只推理，不训练。**
- **工作副本**：`~/audit_ext/paperB_step0/`，内含从 `~/论文1/src` 复制来的代码和本目录的两个脚本。
- **只读的内容**：
  - checkpoint：`~/论文1/results/{main_awgn_v2,cwru_clean_v2,ablation_v3}`；
  - 数据：`~/data_cwru`；

- **运行环境**：系统 python3（torch 2.11、mamba_ssm 2.3.1），这是 paperB 原来用的环境。
- **耗时**：80 个 checkpoint × 10 个 SNR × 2 个测试集，约 6 分钟 GPU 时间。
- **不在范围内**：`hparam_control` 没有存 checkpoint，这一步做不了。

## 做法

两个测试集**只在 Normal 窗口上不同**：
- **orig**：paperB 自己的代码建出来的测试集，`split_seed = 42`，1653 个窗口。其中 Normal 来自 98.mat，共 944 个。
- **x099**：非 Normal 窗口与 orig 完全相同；Normal 换成 99.mat 里真实的 `X099_DE_time` 信号，窗口化方式同 `splits_v2`（长度 1024、步长 512、逐窗 z-score），共 946 个。

数据核对（窗口逐字节 MD5）：
- orig 的 944 个 Normal 测试窗口，**944/944** 在训练集里有逐字节副本，泄漏属实；
- x099 的 946 个 Normal 窗口，**0** 个在训练集里有副本。

为了让两组可以直接比较：
- 两个测试集都把非 Normal 窗口排在前面；
- 每个 SNR 用固定的噪声种子（20261103 + 序号）。

这样非 Normal 窗口在两组里加到的噪声完全相同，两组的差异只来自 Normal 窗口。

## 有效性检查

1. **统计口径一致。** 用 paperB 已发表 summary 里的混淆矩阵算出的每格均值、浓度和崩溃判定，与 paperB 的 `cell_stats.csv` **160/160 格完全一致**。所以本文的浓度定义（各列预测占比的最大值）、≥ 90% 判据和统计方式都与原文相同。
2. **重推理能复现原数。** orig 测试集重新推理的结果与已发表值相比，每格准确率的差中位数为 0.05 pp，最大 0.69 pp。差异只来自评估时噪声的随机实现不同（paperB 评估时没有固定噪声种子）。

## 结果

数字均为每格 5 个种子的均值，比较 x099 对 orig。

### 崩溃格与吸引子类别（核心结论）

- **CWRU 崩溃格：17 → 18。** 原来的 17 格在 x099 下全部仍然崩溃。新增 1 格：`cwru_clean_v2/wdcnn@−2 dB`，浓度从 86.9% 升到 90.8%，刚越过 90% 阈值。
- **吸引子类别没有任何改变**：18 格全部是 Inner Race。
- **−8 dB 的 NA− 行**（对应 `tab:incidence`）：
  - cnn1d、wdcnn、mamba2：准确率都是 14.3%，浓度 100%，不变；
  - drsn：14.5%、浓度 99.8%，不变；
  - lstm：25.6%、浓度 91.5% → 91.6%；
  - vibrmamba：18.7% → 17.6%，浓度 95.6% → 96.7%；
  - transformer：56.1% → 55.8%，浓度 84.2%，未崩溃，不变。
- **挽救效果**（NA+ 减 NA−，在崩溃格上取平均，对应 `tab:rescue` 的 CWRU 部分）：+69.4 pp → +69.6 pp，几乎不变。

### 准确率

- 全部 160 格中，准确率变化的中位数约为 0。|变化| > 1 pp 的有 28 格，> 5 pp 的有 5 格。
- **变化集中在用干净数据训练（NA−）的模型、中等 SNR（−2 到 +6 dB）的格子**，原因是 Normal 召回率下降：
  - cnn1d @ +4 dB：65.0% → 35.3%（Normal 召回 71.6% → 19.8%）
  - cnn1d @ +6 dB：85.9% → 75.9%（95.1% → 77.5%）
  - mamba2（NA−）@ −2 dB：37.7% → 28.7%
  - vibrmamba @ −2 dB：52.2% → 44.8%
  - wdcnn @ +4 dB：85.3% → 80.2%
- **噪声感知训练（NA+，`main_awgn_v2`）几乎不受影响**：70 格中最大变化 2.3 pp，> 1 pp 的只有 3 格；−8 dB 下各架构变化 ≤ 2.3 pp。

### 读法

测试端对 Normal 的“记忆”主要抬高了 NA− 模型在中等 SNR 下的 Normal 召回率，从而抬高了这些格子的准确率。强噪声下塌缩到 Inner Race 的现象、崩溃格集合（只多出 1 个刚过阈值的格）、吸引子类别和挽救效果都不受影响。这与 CNS 项目里同样做法的结果一致（`~/论文CNS/results/AUDIT_CWRU_99mat.md` §3：主导类别 180/180 不变）。

## 局限

1. **这一步只检验测试端。** 训练时模型仍然见过两份 98 的信号（97 + “99”实为 X098），换掉测试 Normal 不等于模型没被这份数据影响。要回答“用正确数据训练会怎样”，必须重训，即 ASSESSMENT 中的最小集 R2 + R3（约 5.4 GPU 小时）。CNS 项目里同样修复加载器后重训，结论是 LEAK_ROBUST。
2. x099 有 946 个 Normal 窗口，orig 是 944 个，类别比例差 0.1%，可以忽略。
3. `hparam_control` 的 CWRU 部分没有存 checkpoint，这一步无法评估。
4. 本步骤是**事后分析，不是预注册**；判读规则没有事先写定。

## 对更正的含义（供作者决定）

- **定性结论（F1 的崩溃与吸引子、挽救效果）在测试端检验下成立。**
- **会变的数字**：
  - CWRU NA− 模型在中等 SNR 下的准确率（`fig:heatmap`、补充材料的逐格表）；
  - CWRU 崩溃格计数，17 → 18，所以总数可能从 25 变为 26；
  - 方法部分关于“所有同工况结果都已做泄漏审计”的表述，需要加上 99.mat 的例外。
- **如果要发正式更正**，最好先用最小集 R2 + R3 重训，用训练端也修正后的数字写更正，而不是用本步骤的数字。本步骤的数字可以作为“测试端影响”的说明附在更正里。
