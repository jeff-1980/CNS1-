# AI 双编码：运行、合并与验证规则 v1（草稿，待 jeff 确认）

## 1. 运行

- 编码者：Claude（Anthropic）与 DeepSeek（`deepseek-chat`），温度 0，提示词 `PROMPT_v1.md`。
- 每个模型对每篇跑 3 次，每次是全新的调用，不带任何上下文。每次请求和返回原样存为 JSON，并记下接口返回的模型名、时间戳和 token 数。
- 80 篇在同一段时间内集中跑完（目标 48 小时内），论文中写明日期。
- 写本草稿的 Claude 会话看过审计结果，**不担任编码者**。Claude 编码只通过不带上下文的新调用进行：有 Anthropic API key 时用 API（固定模型版本，温度 0）；没有时用不带上下文的子代理，只给它提示词和输入包，并在记录中注明“温度不可设”。

## 2. 每个模型的代码

- 同一模型 3 次中至少 2 次相同 → 该模型的代码。
- 3 次各不相同 → 该格记为“不稳定”，进入第 4 步裁定。
- 报告每个模型、每个条目的 3 次一致率（即模型自身的随机性）。

## 3. 证据核验（脚本自动完成）

- 对每格的引句做规范化（合并空白、统一连字符和引号）后，检查它是否逐字出现在输入包中，并检查标注的页码或文件是否正确。
- 不通过 → 该格的证据记为“无效”。
- 引句为空、代码属于“未说明”一类（`U`，S3/S4b 的 `N`/`Q`）→ 视为有效（没有证据本身就是依据）。

## 4. 合并为最终代码

| 情况 | 最终代码 |
|---|---|
| 两模型代码相同，且至少一方证据有效 | 该代码 |
| 两模型代码相同，但双方证据都无效 | 进入人工裁定 |
| 代码不同，只有一方证据有效 | 证据有效一方的代码 |
| 代码不同，双方证据都有效，或任一方不稳定 | 进入人工裁定 |
| 代码不同，双方证据都无效 | 该条目的“未说明”代码（S1/S2/S7 为 `U`，S3/S4b 为 `Q`，S4a 为 `N`，S5 为 `U`），并标记 |

**人工裁定（盲态）：**
- 由第二编码员看两条引句和位置，不告知来自哪个模型，从两个代码中选一个，或选“都不对”并写出依据。
- 裁定只针对这一格，不重新编码整篇。
- 每一次裁定都记录，并报告裁定格数占全部格子的比例。

## 5. 一致性

- 在第 4 步合并之前，按每个模型的代码算每个条目的 Cohen's κ（S5_runs 用完全一致率）。这就是预注册中“两位编码人的 κ”的替代。
- κ < 0.6 的条目：按手册规定合并类别或改写定义后重编，改写前后都报告。

## 6. 人工验证准确率

- 从 79 篇有全文的论文中，用 `numpy.random.default_rng(20261029).choice(79, 20, replace=False)` 抽 20 篇（按 `draw_order` 排序后取下标）。种子在任何编码运行之前登记。
- 第二编码员**先在看不到任何 AI 输出的情况下**，按冻结手册独立编完这 20 篇，交表并存档（记哈希）。只核对 AI 的引句查不出 AI 漏看的内容（例如 AI 填“没有验证集”时没有引句可查），所以先盲编、后比对。
- 交表之后，再把他的代码与 AI 最终代码逐格比对；不一致的格子由他看 AI 的引句复核一次，可以维持或改为 AI 的代码，两次结果都报告（盲编值是主要准确率指标）。
- 第 4 步的盲态裁定也由他在交表之后做，jeff 不参与裁定。
- 报告每个条目和总体的准确率（Wilson 95% 区间）。
- 事先规定：某条目准确率低于 80% 时，该条目在论文中标为“低可信”，只做描述，不进入次要结局 S3 的主要数字。
- 核对员看不到每格是哪个模型给的，也看不到两个模型是否一致。

## 7. 费用估算

- 输入包约 79 篇 × 平均 2–6 万 token，每个模型 3 次，总计约 500–1500 万 token。
- DeepSeek 按官网当前价格估计为几十元人民币；正式运行前先跑 1 篇测得实际 token 数，再报给 jeff 确认。
