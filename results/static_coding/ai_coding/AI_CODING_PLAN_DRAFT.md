## B. 编码提示词（两个模型一字不差）

**输入准备（脚本完成，两个模型用同一份输入）**
- 论文全文：`pdftotext` 提取，每页前加 `[p.N]`。
- 代码：论文中出现代码仓库链接时，脚本浅克隆该仓库（只读，存 `D:\audit_data\coder_repos\`），把文件名含 train / main / run / solver / config 的脚本拼接到输入末尾，每行前加 `[code:路径:行号]`，总长不超过 60 KB；仓库打不开就写 `[code: 无法访问]`。
- 003 无全文，不送模型，直接按手册记 X。

**系统提示**

```
你是一名文献编码员。下面给你一份编码手册和一篇论文（含其代码，如有）。
严格按手册给每个条目选一个代码，不得使用手册以外的代码。
每个条目必须给出支持该代码的原文引句（逐字复制，不改写）和位置（[p.N] 或 [code:路径:行号]）。
找不到依据时，按手册填 U / Q / N 中合适的一项，引句写“无”。
只根据给出的文本判断，不要使用你对这篇论文或作者的任何先验知识。
按下面的 JSON 格式输出，不要输出其他内容。
```

**用户提示**：`<编码手册全文>` + `<论文文本与代码>` + 输出格式：

```json
{"draw_order": 0,
 "S1_split_unit": {"code": "", "quote": "", "loc": ""},
 "S2_validation": {...}, "S3_checkpoint_rule_code": {...},
 "S4a_text_discloses": {...}, "S4b_text_matches_code": {...},
 "S5_runs": {...}, "S5_spread_reported": {...}, "S6_metrics": {...},
 "S7_noise_protocol": {...}, "S8_traceability": {...}}
```

**参数**：两边都用 API 脚本调用，temperature 0。DeepSeek 用 `deepseek-chat`（该名称背后的模型会被不定期升级，所以 80 篇×3 次在同一时段集中跑完，记录接口返回的模型名与日期）；Claude 用 Anthropic API 固定模型快照名。若 Claude 端只能用无头命令行，则如实报告不能设温度。每篇每次运行都存完整输入、输出与时间戳。

## C. 分歧处理与验证规则

1. **引句核验（脚本）**：引句必须能在输入文本中逐字找到（忽略空白与换行）；找不到的那次输出该格作废。
2. **模型内取值**：每个模型 3 次中出现最多的代码为该模型的值；3 次各不相同记为“不稳定”。
3. **模型间取值**：两个模型的值相同 → 终值。不同时：若 6 次有效输出中某代码 ≥ 4 次 → 终值；否则进入人工裁定。
4. **人工裁定**：由同事执行，只看两边的代码和引句，**不显示是哪个模型给的**；仍定不了时，取更有利于“论文做法规范”的一侧（即不利于本审计预期的一侧）。每一处裁定都记录理由。jeff 不参与裁定。
5. **准确性验证**：用 `numpy default_rng(20261017)` 从有全文的 79 篇中无放回抽 20 篇；同事在看到任何 AI 输出之前独立编完这 20 篇，交表后再做第 4 步的裁定。报告 AI 终值与人工逐格一致率、每个条目的 κ 与 bootstrap 95% CI。
6. **报告**：论文中报告模型内一致率、模型间 κ、人工验证一致率、裁定格数；全部提示词、输入、输出、脚本与哈希公开。
