# 预注册 C-INIT：固定初始化后的确认实验（二轮复核 R1）

> 2026-09-26，写于任何 C-INIT 训练之前。触发：二轮复核 R1。历史脚本先构造模型、后设训练种子，因此初始权重取决于上一个实例的评估种子，或新进程的随机状态。
> 历史实例的实际初始权重已按运行日志重建（`init_reconstruction.json`、`init_reconstruction_summary.json`）：2×2 有 5/60 个实例、E5 有 7/189 个实例的初始权重与同架构同种子的其他臂不同。
> 训练在 GPU 上不是逐位可复现的：同一初始权重重训两次，权重最大差 0.45，但 −8 dB 主导类别相同。所以历史重建只能按代码路径推定，不能通过重训逐位验证。
> 本实验**不覆盖**任何历史结果或判定。历史结果在稿件中如实标注为"初始化未完全配对"。
> 代码：`code/cinit.py`；分析：`code/analyze_cinit.py`（运行时校验本文件 SHA256）。

## 1. 修复

- 模型构造前设 `torch.manual_seed(20000 + seed)`，再构造模型；记录初始权重的张量 SHA256（`init_sha256`）。训练函数、数据构造、评估函数、噪声种子均与原实验相同（`arm2x2.train_last`、`arm2x2.evaluate`、`arm2x2.build_arm`、`e5_size_id.build`）
- 训练前检查（smoke）：对每个（架构，种子），分别在"新进程""先跑一次评估之后""打乱构造顺序"三种情况下构造，`init_sha256` 必须相同

## 2. 范围（共 269 个训练实例）

- **C-2×2**：2×2 四臂（C007_R11、C007_R31、CALL_R11、CALL_R31），cnn1d、wdcnn、drsn、lstm，种子 0–4，共 80 个。预算、步数与原实验相同（1900 窗、100 轮 ≈ 3000 步、最后一轮权重）
- **C-E5**：E5 全部 7 个尺寸集合 × 3 次文件抽取（抽取规则与原实验相同，因此文件相同）× wdcnn、drsn、lstm × 种子 0–2，共 189 个
- 运行顺序：wdcnn、cnn1d、drsn 在前，lstm 最后。已完成的实例可断点续跑，续跑不影响初始化

## 3. 有效性条件（硬性）

- 每个（实验，架构，种子）组内，所有臂 / 抽取的 `init_sha256` 必须完全相同；不满足 → 该组记为 INVALID，不参与判定

## 4. 判定

**C-2×2（逐架构，−8 dB 主导类别）**
- wdcnn、drsn、lstm：两个 C007 臂的 IR 占比 ≥ 0.8，且两个 CALL 臂的 OR 占比 ≥ 0.8 → REPLICATED；否则 NOT_REPLICATED
- cnn1d：四臂的 OR 占比均 ≥ 0.8 → REPLICATED（与原结果"不随覆盖切换"一致）
- 比例效应：同一覆盖下 R11 与 R31 的主导类别分布一致（IR 占比差 < 0.4）→ RATIO_NULL_REPLICATED

**C-E5（逐架构）**：用原 E5 预注册的判定规则（`analyze_e5.label`）→ 标签与原 E5 相同 → REPLICATED

**描述性**：逐格与原实验对照主导类别；混合尺寸格（尤其 lstm 的 0.007″ + 0.021″、0.007″ + 0.014″）的一致性

## 5. 对稿件的后果（预先约定）

- C-2×2 中 wdcnn、drsn、lstm 均为 REPLICATED 且 C-E5 三个架构均 REPLICATED → 稿件的主证据改为 C-INIT，可以写"fixed initialization"；原实验作为独立的一次重复，并注明其初始化只部分配对
- 任一主要架构 NOT_REPLICATED → 该架构的主张删除或降为描述，稿件不写"fixed initialization"
- 无论结果如何，原预注册判定（COVERAGE、ANY_LARGER_SIZE）保留原样，不改写

## 6. 局限

- GPU 训练非逐位确定：固定初始化保证配对臂从同一权重出发，不保证训练轨迹逐位相同
- 只修复初始化；数据顺序（`torch.randperm`）本来就由训练种子决定，各臂的数据量相同，打乱顺序在同种子下一致
