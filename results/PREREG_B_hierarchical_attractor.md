## 1. 假说

强噪声下的崩溃是**两级选择**：
- **一级**：崩向 **Healthy 宏类** 还是 **Fault 宏类**
- **二级**：若落入 Fault，具体故障类由损伤构成与架构决定（即 CWRU 上已有的 A1–A3，本线**不再检验**）

**本线只检验一级**：一级选择能否在观察 −8 dB 行为**之前**，由一个**冻结的规则**预测，并在新条件上优于多数类基线。

## 2. 结局定义

- 对每个训练实例，在其测试集上加 −8 dB AWGN（5 次抽样，`torch.manual_seed(5000 + 17·seed + rep)`），取 5 次的众数预测类 `top_mode` 与平均浓度 `conc`
- **宏类靶标** = Healthy（`top_mode == 0`）或 Fault（其余）
- `conc < 0.60` 的实例记为"无吸引子"，不进入准确率计算，但要报告数量；**确认集中无吸引子的实例超过 50% → 本线判 KILLED**（现象本身不存在）

## 3. 候选规则（事先限定为 3 个，不再增加）

| 代号 | 规则 | 依赖 | 与 C5（已证伪）的区别 |
|---|---|---|---|
| **C-a 数据谱平坦度** | 在**干净训练窗**上计算各类的平均谱平坦度 SF（与 WP5 同一函数）；Healthy 类 SF 最高 → 预测 Healthy，否则 Fault | 只依赖训练数据，**训练前即可算**，与模型无关 | C5 的 5 个预测量全部是训练后模型特征空间的几何量，且在具体类层面检验；C-a 是输入空间的数据量，在宏类层面检验 |
| **C-b 纯噪声探针投票** | 用校准窗的逐窗功率生成等功率纯高斯噪声（SNR → −∞），模型预测为 Healthy 的比例 > 0.5 → 预测 Healthy | 依赖训练后模型 | 与 paperB 已发表的"编码器噪声不动点"同源，**新颖性低**；作为机制上的参照 |
| **C-c 探针质心距离** | 最后一个线性层的输入特征：纯噪声探针的质心距离 Healthy 类质心（干净校准窗）比距离最近的 Fault 类质心更近 → 预测 Healthy | 依赖训练后模型 | 与 C5 的 G1（argmin 距离）同类，但在宏类层面、以纯噪声探针为锚 |

## 4. 阶段 B1：开发（已有权重，纯推理）

- 开发集：WP5 已评估的全部实例的 −8 dB 结局（CWRU 40 文件 2×2 与 ext 权重、CWRU 16 文件 E4 / WP1 NA- 的 best 与 final、PU WP2 全部臂）；另加 WP1 JNU 600 rpm 的 NA- 权重
- 对每个实例计算 C-a、C-b、C-c 的预测，与宏类靶标比较
- **选择规则**：选开发准确率最高的候选；准确率相差 ≤ 0.05 时，**按 C-a > C-c > C-b 的顺序优先**（优先与模型无关、新颖性更高的规则）
- **K0（开发即停）**：所选规则的开发准确率不高于开发集多数类基线 → KILLED，不进入确认
- 选定后写 `results/B_RULE_FREEZE.md`（规则代号、全部参数、开发结果），计算 SHA256 并写入注册表，**然后才开始确认集的任何训练**

## 6. 判定（全部满足才算 PASS）

令 A_rule = 冻结规则在确认集（排除无吸引子实例）上的宏类准确率，A_maj = 以**确认集自身**的多数宏类作常数预测的准确率（最强的平凡基线）。

1. 确认集的宏类靶标**同时包含 Healthy 与 Fault**（否则常数预测即 100%，规则不可能更优 → KILLED）
2. **A_rule − A_maj ≥ 0.15**，且配对符号检验（规则对、常数错 vs 规则错、常数对）单侧 p < 0.05
3. **跨数据集**：PU 与 JNU 两个数据集上，规则准确率都 ≥ 该数据集的常数预测准确率，且至少一个严格更高
4. **跨架构**：3 个架构中至少 2 个，规则准确率 > A_maj（在该架构的实例上）

**KILLED**（任一出现即停，不再补救）：
- 以上任一条不满足
- K0 触发
- 需要更换规则、分数或阈值（冻结文件之后不允许任何修改）
- 只能通过删除 Healthy 类才出现结果（本线的结局本身以 Healthy 定义，不允许删除）
