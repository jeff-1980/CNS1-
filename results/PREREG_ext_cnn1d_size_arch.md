## 设计前已知的事实（不是结果）

- 自然 16 文件协议（`cwru_16file_probe`）的"最佳验证集"选模：6/6 个 run 在 **epoch ≤10** 时 val 已达 1.0000，而选模规则只接受严格提升，**选中的是早期 checkpoint**
- 验证集：Val_16 = {Normal_load3, IR007_load0, B007_load1, OR007@6_load3}，与 Train_16 按文件不相交；但其中 3 个 007 文件属于 Train_40 → 对以 Train_40 为池的臂，Val_16 会泄漏。Val_40 不含 B007。**因此"验证集选模"只能在以 Train_16 为池的臂上干净地实现**
- 2×2 中 cnn1d 单个实例约 62 s，wdcnn 12 s，drsn 79 s（GPU 处于温控降频状态）

## 共用的记录方式：训练轨迹上的靶标（所有实验）

每个 run 在训练进度 f ∈ {0.05, 0.10, 0.20, 0.30, 0.50, 0.75, 1.00} 处（向上取整到 epoch）评估 −8 dB 靶标（Test_40，2 次噪声抽样），并在 `torch.random.fork_rng` 内进行，**不扰动训练的随机数流**。
最后一轮权重（f=1.00）与验证集最佳权重（仅限 Train_16 池）另做完整评估：SNR {10, 0, −4, −6, −8}，5 次抽样。

## E1：cnn1d 翻转的来源 —— 2³ 析因（仅 cnn1d）

三个因子（0 = 与 2×2 的 C007_R31 相同；1 = 与自然 16 文件协议相同）：

| 因子 | 0 | 1 |
|---|---|---|
| **ID** 文件身份 | 池 = Train_40 的 Normal + 007 文件（每个故障类 3 个载荷文件） | 池 = Train_16（每个故障类 2 个载荷文件） |
| **N** 训练规模 | 1900 窗：Normal 950，B/IR/OR 316/318/316 | 2844 窗：Normal 1419，每个故障类约 475（Train_16 全量；Train_40 池中每类不放回抽 475） |
| **S** 优化步数 | ≈3000 步 | 4500 步 |

epoch 数 = 步数 / 每 epoch 步数：(N0,S0)=100，(N0,S1)=150，(N1,S0)=67（3015 步），(N1,S1)=100。warmup = round(0.05·E) 个 epoch，cosine 调度按 epoch 更新。
8 个 cell × 5 个种子 = **40 个实例**。Normal 窗口按 (file_id, start) 排序后再抽样，使同一种子在 ID 两个水平间取到**同一批** Normal 窗口；(ID0,N0,S0) 这个 cell 直接复用 2×2 的 `build_arm`，即与 C007_R31 使用相同的数据。

**主结局**：最后一轮权重在 −8 dB 下的 Y = 1[靶标 = IR]。

**端点检查**（任一不通过 → 标签 `ENDPOINT_FAIL`，结果只做描述）：
- (0,0,0) 最后一轮：cnn1d OR ≥ 4/5（复现 2×2 的 C007_R31）
- (1,1,1) 验证集最佳：IR ≥ 4/5（复现自然 16 文件协议的 4/4）

**效应**：
- 主效应 M_F = P(Y | F=1) − P(Y | F=0)，20 对 20；bootstrap 在 8 个 cell 内对实例重抽，10000 次，种子 0
- V 效应（仅限 ID=1 的 4 个 cell，20 个实例配对）：D_V = P(Y_验证集最佳) − P(Y_最后一轮)，在 cell 内对实例做配对 bootstrap
- 每个效应分别标注：CI 下限 > 0.20 → `TOWARD_IR`；CI ⊂ (−0.20, 0.20) → `NO_EFFECT`；CI 上限 < −0.20 → `TOWARD_OR`；其余 → `INDETERMINATE`
- 二阶交互只做描述

## E2：尺寸 vs 故障文件数

以 Train_40 为池，每类 230 窗（受单个文件训练窗数下限 235 约束），R11 → **920 窗**，3000 步（15 步/epoch × 200 epoch，warmup 10），最后一轮权重。

| 臂 | 每个故障类用的文件 |
|---|---|
| `S1L3` | 3 个 007 文件（3 个载荷），每个文件 77/77/76 窗 |
| `S3L1` | 3 个尺寸（007/014/021）各 1 个文件；载荷按 (种子 mod 可用载荷数) 在排序后的列表中选取 |
| `S1L1` | 1 个 007 文件（载荷按 种子 mod 3 选取），230 窗 |

架构 wdcnn、drsn（主分析，每臂合计 n=10）与 cnn1d（单列），3 臂 × 3 架构 × 5 种子 = **45 个实例**。同一种子下三个臂的 Normal 窗口相同。

- **前提条件**：主分析中 P(IR | S1L3) ≥ 0.8；不满足 → `BUDGET_DEPENDENT`（在 920 窗预算下覆盖效应消失），停止进一步解释
- D = P(S1L3) − P(S3L1)，bootstrap 在架构内分层
  - CI 下限 > 0.20 → `SIZE_NOT_FILECOUNT`
  - CI ⊂ (−0.20, 0.20) → `FILECOUNT_OR_LOAD`（每个尺寸只用 1 个文件时，不再翻转）
  - 其余 → `INDETERMINATE`
- S1L1 只做描述
- **解释约束**：S3L1 中不同尺寸的文件必然来自不同载荷，且 014/021 文件还有其他差异（例如部分类别只有 1 个载荷）。`SIZE_NOT_FILECOUNT` 允许的表述仅限于："每类故障文件数相同（3 个）时，让文件在尺寸上变化，而不是在载荷上变化，会使靶标移向 OR"

## E3：lstm / transformer 在 2×2 四臂上

完全复用 2×2 协议（`arm2x2.py`，四臂，5 个种子）→ **40 个实例**。只按架构逐一报告，**不合并**，不给合并标签。每个架构内沿用 2×2 预注册 §6 的规则（CI 在种子层面重抽），标签仅作描述。若浓度 < 0.90（未崩溃），如实报告。

## 运行顺序与降频

E1 → E2 → E3，依次在单块 GPU 上运行，每分钟采样一次 nvidia-smi。E3 耗时最长（预计 transformer 每个实例约 9 分钟），允许在 E1、E2 分析完成后才结束。
