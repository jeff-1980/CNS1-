# 数据地图 v1（2026-11-03）

目的：探测器第 3 层。雷达只能说哪里在升温；金子在"升温方向 × 挖得动的公开多年真实记录"的交集。本表只收**真实运行/事件记录**或已被子刊接受的数据形态，不收实验台预置故障集（那些在 [[管家/Datasets]] 里）。
字段：对象 / 来源与获取（公开=直接下载；申请=注册或签协议）/ 时间跨度 / 真实运行 / 有无事件·干预·维护记录 / 规模 / 拥挤度（粗估：用该数据发表的论文数量级）/ 本机已有。
"拥挤度"与"申请"两列是我的粗估，用前要核。

## E. 用法

1. 对化验前 50 的每个"工程对象"，到本表找对应行：有行且"事件/干预"非空、拥挤低 → 候选进入每日扫描做基线；无行 → 先找数据再谈。
2. 当前最像金子的空位（公开、多年、带事件或干预、拥挤低、机械核心）：
   - 电扶梯机队（MTA、NYC DOB）：无人用这些数据问机械可靠性问题；对象是纯机械；可做维护策略/老化/停运聚集。
   - 铁路延误归因与荷兰列车中断（Network Rail、Rijdende Treinen）：设备原因码齐全，机械可靠性文献几乎没碰。
   - 欧洲机组非计划停运（ENTSO-E/德国 Zenodo）：机组级、原因码，可做"维修后早期失效"复核（SDR 没做成的事）。
   - 核电 LER + PRIS：部件级事件，可靠性文献用得少。
3. 每条进入候选池前照旧过 H1–H5 + 基线 + 杀死测试。本表每两周补一次。
